# AGENTS.md

## Продукт и границы

medi — статическая русскоязычная PWA с тремя named-практиками и одним основным действием. Ценность продукта: после первого полного онлайн-открытия пользователь выбирает «Треугольник дыхания», «Шаманские барабаны» или «Мягкий белый шум» и запускает локальный трек без сети, в том числе с домашнего экрана мобильного устройства. Для дыхательной практики доступны только режимы 3, 5 и 10 минут.

Не добавлять без нового RFC аккаунты, backend, библиотеку треков, дополнительные практики сверх трёх, произвольные таймеры, статистику, аналитику, push, внешние аудиосервисы или сложную навигацию. Сохранять спокойный mobile-first интерфейс, доступность с клавиатуры и screen reader, live-статус, видимый focus и область основного действия не менее 44×44 CSS px. Продуктовые принципы: [PRODUCT.md](PRODUCT.md). Исходные решения и критерии: [docs/rfc/archive/meditation-pwa.md](docs/rfc/archive/meditation-pwa.md), [docs/rfc/archive/second-audio-track.md](docs/rfc/archive/second-audio-track.md), [docs/rfc/archive/third-audio-track.md](docs/rfc/archive/third-audio-track.md), [docs/rfc/archive/breathing-triangle.md](docs/rfc/archive/breathing-triangle.md).

## Окружение и команды

- Node.js 24, версия в `.nvmrc`; зависимости устанавливать только через `npm ci` в CI и на чистом checkout.
- `ffmpeg` и `ffprobe` нужны в `PATH` для аудиопроверок в `tests/audio.test.ts`.
- `npm run dev` — dev-сервер Astro.
- `npm run check` — обязательная диагностика Astro/TypeScript.
- `npm test` — unit- и аудиотесты Vitest; `vitest.config.ts` ограничивает набор файлами `tests/**/*.test.ts`.
- `npm run build` — production-сборка в `dist/` вместе с manifest и service worker.
- `npm run preview` — просмотр сборки.
- `npx playwright install chromium` — однократная установка браузера в новом окружении.
- `npm run test:e2e` — Playwright; команда сама пересобирает сайт с `BASE_PATH=/medi/` и поднимает тестовый static server.
- `npm run test:all` — стандартная полная проверка перед завершением изменений.
- `make build-and-deploy` — check, unit-тесты, сборка и публикация `dist/` в `gh-pages` из любой ветки; `make deploy` — только публикация готового `dist/`.

Не считать работу проверенной только импортами или компиляцией: прогонять поведение, затронутое изменением. Не коммиттить `node_modules/`, `dist/`, `.astro/`, `.audio-work/`, `test-results/` и отчёты Playwright. Локально Playwright может переиспользовать сервер на порту 4321; при несовпадающем `base` сначала остановить старый тестовый сервер, чтобы webServer выполнил новую сборку.

## Архитектурные правила

### Astro, TypeScript и стили

Сайт полностью статический (`output: 'static'`). Интерактивность — клиентский TypeScript и Web API, без React или другого UI-фреймворка. Использовать существующие Tailwind/daisyUI-классы и тему `medi`; не подключать вторую дизайн-систему. Сохранять строгую типизацию и обработку Promise без unhandled rejection.

### Плеер и длительность

Один `<audio preload="auto">` с локальным URL и `loop = true` для всех практик. Воспроизведение начинается только явным действием пользователя. UI синхронизируется с событиями `play`, `pause`, `waiting`, `canplay`, `timeupdate` и `error`, а не с одним успешным вызовом `audio.play()`.

Выбор практики — нативная radio-группа из трёх вариантов в `fieldset` с доступным `legend`. Для «Треугольника дыхания» показывается вторая нативная radio-группа «Длительность практики» с вариантами 3, 5 и 10 минут; для остальных она скрыта. Все варианты доступны касанием, клавиатурой и screen reader, имеют видимый focus и область не менее 44×44 CSS px. По умолчанию выбраны «Треугольник дыхания» и 3 минуты; выбор не сохраняется между запусками.

Смена практики или длительности вызывает `load()`, ставит паузу, сбрасывает `currentTime = 0`, отменяет старый session timer и не вызывает `play()`. Незавершённый `play()` предыдущего выбора, его события и устаревший `AbortError` не должны перезапускать звук, перезаписывать статус нового выбора или вызывать unhandled rejection. Одновременно существует не более одной операции запуска и одного session timer, быстрые переключения оставляют последний выбор.

«Стоп» делает `pause()` и сбрасывает позицию и остаток. Внешняя пауза и буферизация сохраняют позицию и остаток. Окончание дыхательной сессии определяется монотонным deadline на `performance.now()` и `setTimeout`; `timeupdate` и `visibilitychange` проверяют просроченный deadline. По завершении плеер сбрасывает позицию, показывает «Практика завершена» и возвращает «Начать». Часовые практики не используют session timer. Не использовать JS-таймеры для поддержания фонового звука.

Браузер может задержать session timer в фоне или при блокировке: выбранная длительность не гарантирует секундную точность, а остановка может оборвать середину 21-секундного цикла. Не скрывать это ограничение в документации и не имитировать завершение, пока звук продолжается. Короткий MP3-loop также требует устройственной проверки на разрывы.

Ошибка файла возвращает доступное действие запуска, называет выбранную практику и не мешает переключиться на другую. Media Session необязателен: код работает без API и без поддержки отдельных action handlers; метаданные обновляются при смене практики, `nexttrack`/`previoustrack` не регистрируются.

### `base` и публичные ресурсы

Все runtime-ссылки на HTML-ресурсы, аудио, обложки и иконки должны учитывать `import.meta.env.BASE_URL`. В `astro.config.mjs` использовать вычисленный `base` для `manifest.id`, `start_url`, `scope`, иконок и `navigateFallback`. Не добавлять абсолютные пути вида `/audio/...` или `/icons/...`: они ломаются на `https://<user>.github.io/<repo>/`.

`generateSW.navigateFallback` должен быть равен `base`: Astro помещает страницу в precache по URL `base`, а не по `${base}index.html`. Несовпадающий ключ роняет инициализацию service worker с `non-precached-url`.

Для проверки непустого пути использовать:

```bash
BASE_PATH=/medi/ SITE_URL=https://anatolii-iumashev.github.io npm run build
npm run test:e2e
```

### PWA и обновления

PWA построена на `@vite-pwa/astro` с Workbox `generateSW`, `registerType: 'autoUpdate'` и `navigateFallback` внутри `base`. Manifest задаёт `display: 'standalone'` и `display_override: ['minimal-ui', 'standalone', 'browser']`: Android и desktop получают компактную шапку с меню из трёх точек и «Поделиться», а iOS откатывается к `standalone`. Не заменять `display` на `minimal-ui` без `display_override`. При `controllerchange` страница перезагружается только если `<audio>` на паузе: обновление service worker не должно прерывать звучащую практику.

В precache обязаны HTML, JS, CSS, manifest, иконки, обложка и все три runtime MP3 (~41,5 МиБ суммарно в текущей сборке). `maximumFileSizeToCacheInBytes` остаётся 24 МиБ для часовых файлов; при росте аудио проверять лимит и присутствие каждого файла в `dist/sw.js`. WAV-мастера и исходные Opus/WebM в `public/` не добавляются и в `dist/` не публикуются. Workbox добавляет revision query: в проверках сравнивать `new URL(url).pathname`, а не полный URL через `endsWith()`. Основной сценарий не должен зависеть от сетевых fallback-запросов или внешних доменов. Первый запуск офлайн невозможен; очистка site data требует повторного онлайн-открытия и полной загрузки.

### Деплой

Публикация только статического `dist/` в отдельную ветку `gh-pages`; GitHub Pages настроен на **Deploy from a branch** (`gh-pages`, `/ (root)`). Workflow `.github/workflows/deploy.yml` запускается при push в `main` и вручную, выполняет check, unit-тесты, сборку и публикует `dist/` через `peaceiris/actions-gh-pages`. Node в Actions берётся из `.nvmrc`. Локально `make build-and-deploy` делает то же из любой ветки через `gh-pages`; `make deploy` публикует уже собранный `dist/`. В GitHub Actions `site` и `base` выводятся из стандартных `GITHUB_REPOSITORY*`; ручные override — `SITE_URL` и `BASE_PATH`. Не добавлять персональные токены и секреты для штатного Pages-деплоя.

Целевой URL: `https://anatolii-iumashev.github.io/medi/`. Проверять его фактический HTTP-ответ и последний запуск Actions; не утверждать, что сайт доступен, пока workflow и HTTPS URL не проверены.

## Обязательная приёмка

После изменений плеера — unit и E2E-сценарии Start/Stop для всех практик и режимов, сброса позиции и таймера, повторного старта, внешней паузы и остатка, завершения, ошибки, смены выбора во время звучания и pending start, Media Session. После изменений разметки — viewport 360×640, 390×844, 768×1024, отсутствие прокрутки и перекрытий, клавиатура, focus и radio-группы. После изменений PWA или `base` — production build, manifest, пути ресурсов, precache всех трёх MP3 и повторная загрузка каждого трека в offline.

Перед релизом на реальных актуальных iOS/Safari и Android/Chrome отдельно проверить:

1. Установку и standalone-запуск.
2. Полный offline-перезапуск в авиарежиме и запуск каждого трека и каждого режима дыхания.
3. Для 3-минутного режима полную сессию после сворачивания и после блокировки; для 5- и 10-минутного — не менее 5 минут в каждом фоновом сценарии с замером фактического завершения.
4. Непрерывный звук часовых треков не менее 5 минут после сворачивания и блокировки.
5. На слух в наушниках — вдох, полную тишину, затухание «Ом», стык 21-секундного лупа и внутренние стыки часовых треков.
6. Системные метаданные и действия Media Session, включая название выбранной практики.
7. Поведение при звонке/потере аудиофокуса и обновление service worker без принудительного reload.

Эмулятор, fake timers и DevTools не заменяют эти устройственные проверки. Системные прерывания и позднее завершение нельзя маскировать ложным состоянием UI.

## Текущие ограничения

- Происхождение, лицензия и атрибуция всех трёх MP3 не подтверждены: это технические placeholder-файлы. Для нового выдоха использован фрагмент записи Olaf Ruf; право на его распространение и атрибуция не подтверждены.
- Новый тембр и выбранный фрагмент «Ом» ещё не прошли слуховую приёмку владельца; два предыдущих синтезированных варианта были отклонены.
- Реальные iOS/Android, standalone offline, стык короткого лупа, фоновая точность session timer и обновление service worker на устройствах не проверены.
- Часовые файлы получены повторением исходных лупов или длинным фрагментом; их однообразность и качество 48 kbps mono не проверены на слух на реальных устройствах.
- Доступность GitHub Pages зависит от текущего deploy; проверять целевой URL перед отметкой критерия выполненным.

При изменении поведения обновлять соответствующие README.md, PRODUCT.md, RFC и `docs/specs/`; этот AGENTS.md обновлять при изменении архитектуры, команд, карты файлов или правил приёмки. Не хранить в документации секреты, токены и персональные данные.
