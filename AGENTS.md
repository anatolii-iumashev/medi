# AGENTS.md

## Продукт и границы

Medi — статическая русскоязычная PWA с двумя named-практиками и одним основным действием. Ценность продукта: после первого полного онлайн-открытия пользователь выбирает «Тихое дыхание» или «Шаманские барабаны», запускает и останавливает локальный зацикленный трек без сети, в том числе с домашнего экрана мобильного устройства.

Не добавлять без нового RFC аккаунты, backend, библиотеку треков, дополнительные практики сверх двух, таймеры, статистику, аналитику, push, внешние аудиосервисы или сложную навигацию. Сохранять спокойный mobile-first интерфейс, доступность с клавиатуры и screen reader, live-статус, видимый focus и область основного действия не менее 44×44 CSS px. Продуктовые принципы: [PRODUCT.md](PRODUCT.md). Исходные решения и критерии: [docs/rfc/meditation-pwa.md](docs/rfc/meditation-pwa.md), [docs/rfc/second-audio-track.md](docs/rfc/second-audio-track.md).

## Окружение и команды

- Node.js 24, версия в `.nvmrc`; зависимости устанавливать только через `npm ci` в CI и на чистом checkout.
- `npm run dev` — dev-сервер Astro.
- `npm run check` — обязательная диагностика Astro/TypeScript.
- `npm test` — unit-тесты Vitest; `vitest.config.ts` ограничивает набор файлами `tests/**/*.test.ts`.
- `npm run build` — production-сборка в `dist/` вместе с manifest и service worker.
- `npm run preview` — просмотр сборки.
- `npx playwright install chromium` — однократная установка браузера в новом окружении.
- `npm run test:e2e` — Playwright; команда сама пересобирает сайт с `BASE_PATH=/medi/` и поднимает тестовый static server.
- `npm run test:all` — стандартная полная проверка перед завершением изменений.
- `make build-and-deploy` — check, unit-тесты, сборка и публикация `dist/` в `gh-pages` из любой ветки; `make deploy` — только публикация готового `dist/`.

Не считать работу проверенной только импортами или компиляцией: прогонять поведение, затронутое изменением. Не коммиттить `node_modules/`, `dist/`, `.astro/`, `test-results/` и отчёты Playwright. Локально Playwright может переиспользовать сервер на порту 4321; при несовпадающем `base` сначала остановить старый тестовый сервер, чтобы webServer выполнил новую сборку.

## Архитектурные правила

### Astro, TypeScript и стили

Сайт полностью статический (`output: 'static'`). Интерактивность — клиентский TypeScript и Web API, без React или другого UI-фреймворка. Использовать существующие Tailwind/daisyUI-классы и тему `medi`; не подключать вторую дизайн-систему. Сохранять строгую типизацию и обработку Promise без unhandled rejection.

### Плеер

Один `<audio>` с локальным URL и `loop`. Воспроизведение начинается только явным действием пользователя. UI синхронизируется с событиями `play`, `pause`, `waiting`, `canplay` и `error`, а не с одним успешным вызовом `audio.play()`.

Выбор практики — нативная radio-группа из двух вариантов в `fieldset` с доступным `legend`; каждый вариант доступен касанием, клавиатурой и screen reader, имеет видимый focus и область не менее 44×44 CSS px. По умолчанию выбрано «Тихое дыхание»; выбор не сохраняется между запусками.

Смена практики меняет `src` единственного `<audio>`, вызывает `load()`, ставит паузу, сбрасывает `currentTime = 0` и сама не вызывает `play()`. Незавершённый `play()` предыдущего источника, его события и устаревший `AbortError` не должны перезапускать звук, перезаписывать статус нового выбора или вызывать unhandled rejection. Одновременно существует не более одной операции запуска, а быстрые переключения оставляют активным последний выбор.

«Стоп» делает `pause()` и сбрасывает `currentTime = 0`. Внешняя пауза показывает «Начать» и сохраняет позицию. Ошибка файла возвращает доступное действие запуска, называет выбранную практику и не мешает переключиться на другую. Media Session необязателен в браузере: код должен работать без API и без поддержки отдельных action handlers; метаданные обновляются при смене практики, а `nexttrack`/`previoustrack` не регистрируются. Не использовать JS-таймеры для поддержания фонового звука.

### `base` и публичные ресурсы

Все runtime-ссылки на HTML-ресурсы, аудио, обложки и иконки должны учитывать `import.meta.env.BASE_URL`. В `astro.config.mjs` использовать вычисленный `base` для `manifest.id`, `start_url`, `scope`, иконок и `navigateFallback`. Не добавлять абсолютные пути вида `/audio/...` или `/icons/...`: они ломаются на `https://<user>.github.io/<repo>/`.

`generateSW.navigateFallback` должен быть равен `base`: Astro помещает страницу в precache по URL `base`, а не по `${base}index.html`. Несовпадающий ключ роняет инициализацию service worker с `non-precached-url`.

Для проверки непустого пути использовать:

```bash
BASE_PATH=/medi/ SITE_URL=https://anatolii-iumashev.github.io npm run build
npm run test:e2e
```

### PWA и обновления

PWA построена на `@vite-pwa/astro` с Workbox `generateSW`, `registerType: 'autoUpdate'` и `navigateFallback` внутри `base`. Manifest задаёт `display: 'standalone'` и `display_override: ['minimal-ui', 'standalone', 'browser']`: Android и desktop получают компактную шапку с меню из трёх точек и «Поделиться», а iOS, не поддерживающий `minimal-ui`, откатывается к `standalone` и сохраняет запуск с домашнего экрана. Не заменять `display` на `minimal-ui` без `display_override`: Safari в этом случае может открыть ярлык в обычной вкладке. Не добавлять принудительный reload при обновлении service worker во время воспроизведения. Новая сборка применяется на следующей навигации/запуске; версионирование precache и удаление устаревших кэшей остаются за Workbox.

В precache обязаны HTML, JS, CSS, manifest, иконки, обложка и оба полных часовых MP3 (~42 МБ суммарно). `maximumFileSizeToCacheInBytes` поднят до 24 МиБ, потому что каждый файл больше прежнего лимита 8 МиБ; при дальнейшем росте аудио проверять лимит и фактическое присутствие каждого файла в `dist/sw.js`. WAV-мастера и Opus-исходники в `public/` не добавляются и в `dist/` не публикуются. Workbox добавляет revision query к закэшированным URL: в проверках сравнивать `new URL(url).pathname`, а не полный URL через `endsWith()`. Основной сценарий не должен зависеть от сетевых fallback-запросов или внешних доменов. Первый запуск офлайн невозможен; очистка site data требует повторного онлайн-открытия и повторной загрузки ~42 МБ.

### Деплой

Публикация только статического `dist/` в отдельную ветку `gh-pages`; GitHub Pages настроен на **Deploy from a branch** (`gh-pages`, `/ (root)`). Workflow `.github/workflows/deploy.yml` запускается при push в `main` и вручную, выполняет check, unit-тесты, сборку и публикует `dist/` через `peaceiris/actions-gh-pages`. Node в Actions берётся из `.nvmrc`. Локально `make build-and-deploy` делает то же из любой ветки через `gh-pages`; `make deploy` публикует уже собранный `dist/`. В GitHub Actions `site` и `base` выводятся из стандартных `GITHUB_REPOSITORY*`; ручные override — `SITE_URL` и `BASE_PATH`. Не добавлять персональные токены и секреты для штатного Pages-деплоя.

Целевой URL: `https://anatolii-iumashev.github.io/medi/`. Проверять его фактический HTTP-ответ и последний запуск Actions; не утверждать, что сайт доступен, пока workflow и HTTPS URL не проверены.

## Обязательная приёмка

После изменений плеера — unit и E2E-сценарии Start/Stop для обеих практик, сброса позиции, повторного старта, внешней паузы, ошибки, смены источника во время звучания и pending start, Media Session. После изменений разметки — viewport 360×640, 390×844, 768×1024, отсутствие горизонтальной прокрутки, клавиатура, focus и выбор практики. После изменений PWA или `base` — production build, manifest, пути ресурсов, precache обоих MP3 и повторная загрузка каждого трека в offline.

Перед релизом на реальных актуальных iOS/Safari и Android/Chrome отдельно проверить:

1. Установку и standalone-запуск.
2. Полный offline-перезапуск в авиарежиме после первого онлайн-открытия и запуск каждого трека.
3. Непрерывный звук не менее 5 минут после сворачивания PWA для каждого трека.
4. Непрерывный звук не менее 5 минут после блокировки экрана для каждого трека.
5. Системные метаданные и действия Media Session там, где они поддерживаются, включая название выбранной практики.
6. Поведение при звонке/потере аудиофокуса и обновление service worker без принудительного reload.
7. Внутренние стыки часовых лупов и поведение при переходе через час на слух в наушниках; подтверждённый тик устраняется из WAV-мастера до релиза.

Эмулятор и DevTools не заменяют эти устройственные проверки. Системные прерывания нельзя маскировать ложным состоянием UI.

## Текущие ограничения

- Происхождение, лицензия и атрибуция обоих MP3 не подтверждены: это технические placeholder-файлы, не согласованные финальные треки.
- Часовые файлы получены повторением исходных лупов; однообразность повторов и качество 48 kbps mono не проверены на слух на реальных устройствах.
- Реальные iOS/Android, standalone offline, пятиминутный фон для каждого трека и обновление service worker на устройствах не проверены.
- Доступность GitHub Pages зависит от текущего deploy; проверять целевой URL перед отметкой критерия выполненным.

При изменении поведения обновлять соответствующие README.md, PRODUCT.md, RFC и `docs/specs/`; этот AGENTS.md обновлять при изменении архитектуры, команд, карты файлов или правил приёмки. Не хранить в документации секреты, токены и персональные данные.
