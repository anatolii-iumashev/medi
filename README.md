# medi

Одностраничная PWA с тремя спокойными практиками. Приложение запускает локальный луп «Треугольник дыхания», «Шаманские барабаны» или «Мягкий белый шум», показывает фактическое состояние звука и после первого полного онлайн-открытия работает без сети. Для дыхательной практики доступны сессии на 3, 5 и 10 минут.

## Возможности и границы

- Три практики и одна основная кнопка «Начать» / «Стоп» в нижнем dock. Выбранная практика и её краткое описание всегда видны над панелью.
- Выбор практики — в меню «Звук», единственная настройка (длительность дыхания) — в меню «Настройки». Оба меню открываются вверх, закрываются по выбору, `Escape` и касанию вне меню и возвращают фокус на свою кнопку.
- Логотип окружён спокойным свечением в цвете темы; при системном уменьшении движения анимация полностью отключается, статическая подсветка остаётся.
- «Треугольник дыхания» повторяет 21-секундный цикл: 7 секунд белого шума для вдоха, 7 секунд тишины и 7 секунд человеческого «Ом» с затуханием. Режимы 3, 5 и 10 минут видны только для этой практики; по умолчанию выбраны 3 минуты.
- «Стоп» останавливает звук и возвращает трек и таймер в начало; повторный запуск начинает практику сначала. После завершения сессии появляется статус «Практика завершена».
- Смена практики или длительности останавливает текущий звук, сбрасывает позицию и отсчёт, но не запускает звук автоматически. Выбор не сохраняется между перезапусками.
- Два остальных трека длятся около часа и зациклены. Все источники локальные; во время работы нет YouTube и внешних аудиосервисов.
- Media Session передаёт системе название выбранной практики, обложку и действия play, pause и stop там, где API поддерживается.
- Service worker предкэширует страницу, скрипты, стили, иконки, manifest и все три runtime MP3 (~41,5 МиБ).
- Установка на домашний экран через меню браузера; на iOS — через «Поделиться» → «На экран “Домой”». Отдельного блока установки в интерфейсе нет, чтобы экран оставался компактным.
- На Android приложение открывается в `minimal-ui`: шапка с названием и доменом, меню из трёх точек с действием «Поделиться»; на iOS сохраняется обычный standalone-запуск.

В MVP нет аккаунтов, библиотеки треков, произвольных таймеров, статистики, аналитики, push-уведомлений, backend и нативных приложений. Единственный таймер ограничивает выбранную длительность «Треугольника дыхания» и не поддерживает фоновый звук.

## Стек

Astro 7 генерирует статический сайт, Tailwind CSS 4 и daisyUI 5 отвечают за интерфейс, `@vite-pwa/astro` и Workbox — за manifest и service worker. Интерактивность написана на TypeScript и стандартных Web API без клиентского UI-фреймворка. Публикация настроена через GitHub Actions и GitHub Pages.

## Локальная разработка

Требуется Node.js 24 (версия зафиксирована в [.nvmrc](.nvmrc)) и npm. Для аудиопроверок также нужны `ffmpeg` и `ffprobe`, доступные в `PATH`.

```bash
nvm use
npm ci
npm run dev
```

Astro по умолчанию открывает сайт на `http://localhost:4321/`.

Сборка и локальный просмотр результата:

```bash
npm run build
npm run preview
```

Для проверки GitHub Pages-подпути локально:

```bash
BASE_PATH=/medi/ SITE_URL=https://anatolii-iumashev.github.io npm run build
node tests/e2e/static-server.mjs /medi/
```

В этом случае приложение доступно на `http://localhost:4321/medi/`. Команда `npm run preview` использует корневой `http://localhost:4321/` независимо от собранного `base`; для проверки подпути нужен указанный static server.

## Проверки

В новом окружении один раз установите браузер Playwright:

```bash
npx playwright install chromium
```

Команды проекта:

```bash
npm run check     # типы и диагностика Astro/TypeScript
npm test          # unit-тесты плеера, таймера, практик и MP3
npm run build     # статическая сборка и генерация PWA
npm run test:e2e  # адаптивность, плеер, base, precache и офлайн-сценарий
npm run test:all  # все проверки выше в рабочей последовательности
```

E2E-тесты сами собирают сайт с `BASE_PATH=/medi/` и запускают статический сервер с поддержкой HTTP Range для аудио. Vitest собирает только unit-тесты `tests/**/*.test.ts`; Playwright-файлы остаются в отдельном запуске.

## Установка и использование PWA

Для установки нужен HTTPS либо localhost.

1. Откройте сайт в Chrome на Android или Safari на iOS.
2. На Android нажмите «Установить приложение», если появилась кнопка, либо выберите установку в меню браузера.
3. На iOS откройте «Поделиться» → «На экран “Домой”».
4. При первом открытии оставайтесь онлайн, пока страница и все аудиофайлы полностью не загрузятся (~41,5 МиБ), а service worker не активируется.
5. Откройте приложение с домашнего экрана, выберите практику в меню «Звук» и нажмите «Начать». Для «Треугольника дыхания» сначала выберите 3, 5 или 10 минут в меню «Настройки». Для остановки и сброса позиции нажмите «Стоп».

Проверка офлайн-режима: после успешного первого открытия закройте PWA, включите авиарежим и снова откройте её с домашнего экрана. Интерфейс должен загрузиться, все практики должны выбираться, а кнопки «Начать» и «Стоп» — работать без сети.

На Android установленное приложение открывается в режиме `minimal-ui`: сверху видна компактная шапка с названием и доменом, а в меню из трёх точек доступно «Поделиться» — оно отправляет ссылку на приложение. Отдельного APK у PWA нет: для распространения именно APK-файла нужна TWA-обёртка и публикация в магазине. На iOS Safari не поддерживает `minimal-ui`, поэтому там сохраняется `standalone`-запуск без браузерной шапки.

Первый запуск без сети невозможен. Очистка site data удаляет кэш, после неё снова нужно полное онлайн-открытие. Если аудио недоступно, приложение показывает ошибку вместо ложного состояния воспроизведения.

Фоновый звук обеспечивается нативным медиастеком браузера и ОС. Таймер выбранной сессии использует `performance.now()` и `setTimeout`, сохраняет остаток при паузе и буферизации, но браузер может задержать его после сворачивания или блокировки экрана. Поэтому звук иногда продолжается дольше выбранных 3/5/10 минут; секундная точность в фоне не гарантируется. Звонок, потеря аудиофокуса и энергосбережение также могут прервать воспроизведение. Проверки на реальных актуальных iOS/Safari и Android/Chrome обязательны перед релизом; браузерные E2E их не заменяют.

## Аудио, права и атрибуция

В приложении три локальных MP3; все входят в precache:

- [`public/audio/breathing-triangle.mp3`](public/audio/breathing-triangle.mp3) — практика «Треугольник дыхания», ровно 21 секунда, моно, 48 кГц, 48 kbps, около 124 КиБ. Вдох 0:00–0:07 взят из 30–37-й секунды соседнего белого шума; задержка 0:07–0:14 — цифровая тишина; выдох 0:14–0:21 — фрагмент 150,5–157,5 секунды записи [«Мантра ОМ для Медитации»](https://www.youtube.com/watch?v=srYk8ek-QNk), Olaf Ruf, с двухсекундным затуханием.
- [`public/audio/shamanic-drums-loop.mp3`](public/audio/shamanic-drums-loop.mp3) — практика «Шаманские барабаны», 3616 секунд (60:16), моно, 48 кГц, 48 kbps, примерно 21,7 МБ. Подготовленный 32-секундный луп повторён 113 раз на уровне сэмплов, без пауз между повторами.
- [`public/audio/soft-white-noise.mp3`](public/audio/soft-white-noise.mp3) — практика «Мягкий белый шум», 3600 секунд (60:00), моно, 48 кГц, 48 kbps, примерно 21,6 МБ. Непрерывный час из [видео с мягким белым шумом](https://youtu.be/Og40mpl8VNc); граница файла сведена двухсекундным кроссфейдом.

Часовые файлы выбраны потому, что Safari/iOS может добавлять разрыв при `loop` короткого MP3. Для дыхательной практики владелец сознательно выбрал короткий луп и программную длительность вместо трёх длинных файлов, поэтому стык 21-секундного цикла требует отдельной слуховой проверки. WAV-мастера и исходные Opus/WebM в runtime не публикуются.

Исполнитель в Media Session — medi; обложка общая. По умолчанию при каждом открытии выбран «Треугольник дыхания» и режим 3 минуты; выбор между перезапусками не сохраняется.

Происхождение файлов, права на их распространение, лицензия и необходимая атрибуция в репозитории не подтверждены. Это относится и к новому фрагменту записи Olaf Ruf. До подтверждения все три файла нельзя считать согласованными релизными треками. Для финального релиза нужно подтвердить права или заменить их разрешённым к распространению аудио и указать здесь авторов, источники и лицензии. `maximumFileSizeToCacheInBytes` в [`astro.config.mjs`](astro.config.mjs) поднят до 24 МиБ: файл больше лимита Workbox не попадёт в precache.

## Публикация на GitHub Pages

Приложение открывается по адресу [https://anatolii-iumashev.github.io/medi/](https://anatolii-iumashev.github.io/medi/) после успешного деплоя. Актуальный статус проверяется по этому URL и в GitHub Actions; не считайте сайт доступным только по наличию workflow.

Собранный сайт публикуется в отдельную ветку `gh-pages`, а не в `main`. Один раз включите Pages: **Settings → Pages → Build and deployment → Source → Deploy from a branch**, ветка `gh-pages`, папка `/ (root)`. После этого каждый новый коммит в `gh-pages` обновляет сайт.

Workflow [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) запускается при push в `main` и вручную через `workflow_dispatch`: устанавливает Node.js из `.nvmrc`, выполняет `npm ci`, проверки типов, unit-тесты, сборку и публикует `dist/` в `gh-pages`. Персональные токены не нужны.

Локально деплой работает из любой ветки:

```bash
make build-and-deploy
```

Команда прогоняет `check`, unit-тесты и production-сборку с путями Pages, затем публикует `dist/` в `gh-pages` через `gh-pages`. Публикуется текущее состояние рабочего дерева, включая незакоммиченные изменения. Отдельный `make deploy` публикует уже собранный `dist/` без пересборки.

В GitHub Actions `site` и `base` вычисляются из `GITHUB_REPOSITORY_OWNER` и `GITHUB_REPOSITORY`; Makefile передаёт `SITE_URL` и `BASE_PATH` (по умолчанию `https://anatolii-iumashev.github.io` и `/medi/`). После первого успешного деплоя проверьте прямой заход, перезагрузку, standalone-запуск и повторный push.
