# Medi

Одностраничная PWA с двумя спокойными практиками. Приложение запускает локальный зацикленный трек «Тихое дыхание» или «Шаманские барабаны», показывает фактическое состояние звука и после первого полного онлайн-открытия работает без сети.

## Возможности и границы

- Ровно две практики и одна основная кнопка: «Начать» / «Стоп».
- «Стоп» останавливает звук и возвращает трек в начало; повторный запуск начинает практику сначала.
- Смена практики останавливает текущий звук, сбрасывает позицию и не запускает новый файл автоматически.
- Оба локальных трека длятся около часа и зациклены, поэтому стык не достигается за обычную сессию. Без YouTube и внешних аудиосервисов.
- Media Session передаёт системе название выбранной практики, обложку и действия play, pause и stop там, где API поддерживается.
- Service worker предкэширует страницу, скрипты, стили, иконки, manifest и оба часовых MP3 (~42 МБ).
- Установка на домашний экран через нативный запрос браузера или инструкцию для iOS.
- На Android приложение открывается в `minimal-ui`: шапка с названием и доменом, меню из трёх точек с действием «Поделиться»; на iOS сохраняется обычный standalone-запуск.

В MVP нет аккаунтов, библиотеки треков, таймеров, статистики, аналитики, push-уведомлений, backend и нативных приложений.

## Стек

Astro 7 генерирует статический сайт, Tailwind CSS 4 и daisyUI 5 отвечают за интерфейс, `@vite-pwa/astro` и Workbox — за manifest и service worker. Интерактивность написана на TypeScript и стандартных Web API без клиентского UI-фреймворка. Публикация настроена через GitHub Actions и GitHub Pages.

## Локальная разработка

Требуется Node.js 24 (версия зафиксирована в [.nvmrc](.nvmrc)) и npm.

```bash
nvm use
npm ci
npm run dev
```

Astro по умолчанию открывает сайт на `http://localhost:4321/`.

Сборка и локальный просмотр результата:

```bash
npm run build
npm run preview
```

Для проверки GitHub Pages-подпути локально:

```bash
BASE_PATH=/medi/ SITE_URL=https://anatolii-iumashev.github.io npm run build
node tests/e2e/static-server.mjs /medi/
```

В этом случае приложение доступно на `http://localhost:4321/medi/`. Команда `npm run preview` использует корневой `http://localhost:4321/` независимо от собранного `base`; для проверки подпути нужен указанный static server.

## Проверки

В новом окружении один раз установите браузер Playwright:

```bash
npx playwright install chromium
```

Команды проекта:

```bash
npm run check     # типы и диагностика Astro/TypeScript
npm test          # unit-тесты состояния плеера и Media Session
npm run build     # статическая сборка и генерация PWA
npm run test:e2e  # адаптивность, плеер, base, precache и офлайн-сценарий
npm run test:all  # все проверки выше в рабочей последовательности
```

E2E-тесты сами собирают сайт с `BASE_PATH=/medi/` и запускают статический сервер с поддержкой HTTP Range для аудио. Vitest собирает только unit-тесты `tests/**/*.test.ts`; Playwright-файлы остаются в отдельном запуске.

## Установка и использование PWA

Для установки нужен HTTPS либо localhost.

1. Откройте сайт в Chrome на Android или Safari на iOS.
2. На Android нажмите «Установить приложение», если появилась кнопка, либо выберите установку в меню браузера.
3. На iOS откройте «Поделиться» → «На экран “Домой”».
4. При первом открытии оставайтесь онлайн, пока страница и оба часовых аудиофайла полностью не загрузятся (~42 МБ), а service worker не активируется.
5. Откройте приложение с домашнего экрана, выберите «Тихое дыхание» или «Шаманские барабаны» и нажмите «Начать». Для остановки и сброса позиции нажмите «Стоп».

Проверка офлайн-режима: после успешного первого открытия закройте PWA, включите авиарежим и снова откройте её с домашнего экрана. Интерфейс должен загрузиться, обе практики должны выбираться, а кнопки «Начать» и «Стоп» — работать без сети.

На Android установленное приложение открывается в режиме `minimal-ui`: сверху видна компактная шапка с названием и доменом, а в меню из трёх точек доступно «Поделиться» — оно отправляет ссылку на приложение. Отдельного APK у PWA нет: для распространения именно APK-файла нужна TWA-обёртка и публикация в магазине. На iOS Safari не поддерживает `minimal-ui`, поэтому там сохраняется `standalone`-запуск без браузерной шапки.

Первый запуск без сети невозможен. Очистка site data удаляет кэш, после неё снова нужно полное онлайн-открытие. Если аудио недоступно, приложение показывает ошибку вместо ложного состояния воспроизведения.

Фоновый звук обеспечивается нативным медиастеком браузера и ОС, а не JavaScript-таймером. Звонок, потеря аудиофокуса, энергосбережение или нехватка ресурсов могут прервать воспроизведение. Пятиминутные проверки после сворачивания и блокировки экрана на реальных актуальных iOS/Safari и Android/Chrome обязательны перед релизом; браузерные E2E-тесты их не заменяют.

## Аудио, права и атрибуция

В приложении два локальных MP3; оба входят в precache:

- [`public/audio/meditation.mp3`](public/audio/meditation.mp3) — практика «Тихое дыхание», 3548 секунд (59:08), моно, 48 кГц, 48 kbps, примерно 21,3 МБ. Исходный шестиминутный трек сведён в бесшовную петлю с кроссфейдом и повторён до часа.
- [`public/audio/shamanic-drums-loop.mp3`](public/audio/shamanic-drums-loop.mp3) — практика «Шаманские барабаны», 3616 секунд (60:16), моно, 48 кГц, 48 kbps, примерно 21,7 МБ. Подготовленный 32-секундный луп повторён 113 раз на уровне сэмплов, без пауз между повторами.

Длинные файлы выбраны потому, что Safari/iOS добавляет разрыв при `loop` короткого MP3. Часовой файл не доходит до стыка за обычную сессию, а внутри него нет пауз. WAV-мастера и Opus-исходники в runtime не публикуются.

Исполнитель в Media Session — Medi; обложка общая. По умолчанию при каждом открытии выбрано «Тихое дыхание», выбор между перезапусками не сохраняется.

Происхождение файлов, права на их распространение, лицензия и необходимая атрибуция в репозитории не подтверждены. До подтверждения оба файла нельзя считать согласованными релизными треками. Для финального релиза нужно заменить их разрешённым к распространению аудио и указать здесь авторов, источники и лицензии. `maximumFileSizeToCacheInBytes` в [`astro.config.mjs`](astro.config.mjs) поднят до 24 МиБ: файл больше лимита Workbox не попадёт в precache.

## Публикация на GitHub Pages

Приложение открывается по адресу [https://anatolii-iumashev.github.io/medi/](https://anatolii-iumashev.github.io/medi/) после успешного деплоя. Актуальный статус проверяется по этому URL и в GitHub Actions; не считайте сайт доступным только по наличию workflow.

Собранный сайт публикуется в отдельную ветку `gh-pages`, а не в `main`. Один раз включите Pages: **Settings → Pages → Build and deployment → Source → Deploy from a branch**, ветка `gh-pages`, папка `/ (root)`. После этого каждый новый коммит в `gh-pages` обновляет сайт.

Workflow [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) запускается при push в `main` и вручную через `workflow_dispatch`: устанавливает Node.js из `.nvmrc`, выполняет `npm ci`, проверки типов, unit-тесты, сборку и публикует `dist/` в `gh-pages`. Персональные токены не нужны.

Локально деплой работает из любой ветки:

```bash
make build-and-deploy
```

Команда прогоняет `check`, unit-тесты и production-сборку с путями Pages, затем публикует `dist/` в `gh-pages` через `gh-pages`. Публикуется текущее состояние рабочего дерева, включая незакоммиченные изменения. Отдельный `make deploy` публикует уже собранный `dist/` без пересборки.

В GitHub Actions `site` и `base` вычисляются из `GITHUB_REPOSITORY_OWNER` и `GITHUB_REPOSITORY`; Makefile передаёт `SITE_URL` и `BASE_PATH` (по умолчанию `https://anatolii-iumashev.github.io` и `/medi/`). После первого успешного деплоя проверьте прямой заход, перезагрузку, standalone-запуск и повторный push.
