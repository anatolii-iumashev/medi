# Spec: Три практики, переключатель аудиотреков и длительность дыхания

> Спека описывает актуальный набор из трёх практик после последовательных поставок второго и третьего трека и замены первой практики на «Треугольник дыхания».

## Что сделано

### Набор практик и файлы

- В `src/scripts/practices.ts` задан статический typed-набор ровно из трёх практик с base-aware URL. Первая и выбранная по умолчанию — «Треугольник дыхания».
- Все runtime-файлы — локальные MP3, моно, 48 кГц, 48 kbps:
  - «Треугольник дыхания» — `public/audio/breathing-triangle.mp3`, ровно 21 с, ~124 КиБ. Цикл: 0:00–0:07 вдох из 30–37-й секунды соседнего белого шума; 0:07–0:14 цифровая тишина; 0:14–0:21 выдох из записи [«Мантра ОМ для Медитации»](https://www.youtube.com/watch?v=srYk8ek-QNk), Olaf Ruf, диапазон 150,5–157,5 с, с двухсекундным затуханием.
  - «Шаманские барабаны» — `public/audio/shamanic-drums-loop.mp3`, 3616 с, ~21,7 МБ; исходный 32-секундный луп повторён 113 раз без пауз.
  - «Мягкий белый шум» — `public/audio/soft-white-noise.mp3`, 3600 с, ~21,6 МБ; непрерывный час из видео [(No Ads) 10 Hours of Soft White Noise | Black Screen for Sleep](https://youtu.be/Og40mpl8VNc) (Let's Find Out).
- Прежний `public/audio/meditation.mp3` и промежуточные файлы 3/5/10 минут удалены из runtime. WAV и исходный WebM не публикуются.

### Интерфейс

- `MeditationPlayer.astro` содержит нативную radio-группу практик в `fieldset` с доступным `legend`. Каждый вариант доступен касанием, клавиатурой и screen reader, имеет видимый focus и область не менее 44×44 CSS px.
- Для «Треугольника дыхания» показывается вторая radio-группа «Длительность практики» с вариантами 3, 5 и 10 минут; по умолчанию выбраны 3 минуты. Для остальных практик группа скрыта.
- Подсказка рядом с первой практикой: «Вдох 7 с · тишина 7 с · выдох 7 с». Выбор длительности сохраняется при временном переключении практики внутри страницы, но не между перезапусками; `localStorage` не используется.
- На экране остаются бренд medi и одна основная кнопка «Начать»/«Стоп». E2E подтверждают компоновку 360×640, 390×844 и 768×1024 без прокрутки и перекрытий.

### Плеер и session timer

- Один `<audio preload="auto" loop>` меняет `src` при выборе практики. Все три практики используют нативный `loop = true`.
- Смена практики или длительности останавливает звук, сбрасывает позицию и session timer, вызывает `load()` и не вызывает `play()`.
- Для дыхательной практики отсчёт начинается по фактическому `play`. Deadline вычисляется через `performance.now()`, завершение планируется одним `setTimeout`; `timeupdate` и `visibilitychange` проверяют просроченный deadline.
- Внешняя пауза и буферизация сохраняют позицию и остаток. «Стоп» сбрасывает оба. По завершении плеер ставит паузу, сбрасывает позицию, показывает «Практика завершена», возвращает «Начать» и переводит Media Session в `none`.
- Часовые практики не используют session timer. Защита поколений отсекает устаревшие `play()` и `AbortError`; быстрые изменения оставляют последний выбор без unhandled rejection.
- Media Session получает название выбранной практики, общую обложку и play/pause/stop; `nexttrack`/`previoustrack` не регистрируются.

### PWA и проверки

- Все три MP3 входят в precache; `maximumFileSizeToCacheInBytes` — 24 МиБ. Production build содержит 13 precache-записей суммарно ~41,5 МиБ.
- `tests/player.test.ts` покрывает запуск/остановку, паузу и остаток, буферизацию, все режимы на fake timers, отмену таймера, гонки и Media Session.
- `tests/audio.test.ts` через `ffprobe` и декодированный PCM проверяет 21-секундный MP3, формат, семисекундную тишину, затухание выдоха и отсутствие аномальных скачков на границах и стыке.
- `tests/e2e/meditation.spec.ts` покрывает доступность, все источники и длительности, завершение управляемыми часами, base, manifest, precache и offline-reload.
- `npm run test:all` пройден: Astro/TypeScript без ошибок, 29 unit/аудиотестов и 12 E2E зелёные.

## Ключевые решения

- Один `<audio>` с динамическим `src` и одна основная кнопка сохраняют единое состояние плеера.
- По прямому решению владельца используется один 21-секундный луп и программная длительность вместо трёх MP3 на 180, 300 и 600 секунд. Это уменьшает precache, но возвращает риск разрыва короткого MP3-loop и задержки таймера в фоне.
- Два синтезированных варианта «Ом» отклонены владельцем. Итоговый технический вариант собран из соседнего белого шума, цифровой тишины и указанной владельцем человеческой записи.
- Часовые файлы остаются длинными, поскольку Safari/iOS может добавлять слышимый разрыв при коротком MP3-loop. Для новой практики это ограничение сознательно принято и требует устройственной проверки.
- JS не поддерживает фоновый звук, но ограничивает сессию. Секундная точность завершения в фоне не обещается.

## Отклонения от RFC

- Первоначальный RFC требовал три заранее подготовленных файла и запрещал JS-таймер; владелец изменил решение на один луп и программный отсчёт уже во время реализации. RFC обновлён до дальнейших изменений кода.
- Порядок и содержимое фаз также изменены владельцем после слуховой приёмки: вдох → тишина → затухающий выдох, без синтезированной основы и стуков.
- Для загрузки указанного YouTube-источника потребовался актуальный `yt-dlp` 2026.10.26: установленная версия 2026.03.17 получала HTTP 403. Временный инструмент и WebM остались только в игнорируемом `.audio-work/` и не добавлены в runtime или зависимости проекта.

## Известные ограничения / дальнейшие шаги

- Права, лицензия и атрибуция всех трёх MP3 не подтверждены; файлы остаются техническими нерелизными placeholder-ами. Для нового фрагмента Olaf Ruf необходимо отдельно подтвердить право распространения и атрибуцию.
- Новый фрагмент «Ом» ещё не прошёл слуховую приёмку владельца. Качество и однообразность часовых треков на реальных устройствах также не подтверждены.
- Реальные iOS/Safari и Android/Chrome не проверены: standalone offline, стык 21-секундного лупа, фоновые сценарии, фактическое время завершения, Media Session, аудиофокус и обновление service worker обязательны перед релизом.
- Браузер может задержать session timer после сворачивания или блокировки; звук способен продолжаться дольше выбранного режима. Завершение может оборвать середину цикла без заранее записанного финального затухания.
