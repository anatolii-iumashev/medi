# Последняя выбранная практика запоминается между запусками

## TL DR

Приложение всегда открывалось с практикой из настройки «Аудио по умолчанию», а выбор в меню «Звук» жил только до закрытия. Владелец ожидает обратного: если в последней сессии слушали «Мягкий белый шум», следующее открытие начинается с него, а не с сохранённого ранее «Шаманских барабанов». Меняем правило: выбор практики в меню «Звук» записывается в тот же ключ `medi:default-practice`, поэтому последняя выбранная практика одновременно является стартовой и отражается на странице настроек.

## Контекст

[player-dock-and-aura.md](./archive/2611/player-dock-and-aura.md) ввёл явную настройку «Аудио по умолчанию» и зафиксировал, что сам выбор в сессии не сохраняется. [second-audio-track.md](./archive/2611/second-audio-track.md) и [third-audio-track.md](./archive/2611/third-audio-track.md) сохранили это правило. На практике оно даёт неожиданный сценарий: пользователь меняет звук в меню перед сном, закрывает PWA, а утром получает практику, которую выбирал несколько недель назад в настройках, — и воспринимает это как потерю выбора.

Двух источников истины быть не должно: отдельный ключ «последняя практика» перекрывал бы явную настройку и делал бы её radio-вариант недостоверным. Поэтому используется один ключ.

## Назначение и цели

- Следующее открытие приложения начинается с практики, которую слушали последней.
- Страница настроек показывает то же значение: «Аудио по умолчанию» остаётся честным описанием стартовой практики.
- Выбор практики по-прежнему не запускает звук, не меняет текущую сессию при смене настройки и не влияет на остальные гарантии плеера.
- Ничего не добавляется в интерфейс: настроек остаётся две, новых экранов и переключателей нет.

## Составляющие и особенности

### 1. Хранение

`src/scripts/preferences.ts` получает `writeDefaultPractice(id)` — запись в уже существующий ключ `medi:default-practice` через тот же безопасный `write()`, что и тема. При недоступном `localStorage` (приватный режим, заблокированные cookies) запись молча не сохраняется, поведение сессии не меняется.

### 2. Плеер

`initPlayer()` в `src/scripts/player.ts` при событии `change` выбранной radio-группы вызывает `player.select(practice)`, `writeDefaultPractice(practice.id)` и обновляет видимый блок практики. Сам `MeditationPlayer` остаётся state machine и предпочтения не пишет — он только читает стартовое значение при инициализации, как и раньше. Смена длительности по-прежнему не сохраняется.

### 3. Настройки

`initPreferences()` уже читает `medi:default-practice` и выставляет соответствующий radio, поэтому после выбора в меню «Звук» страница настроек показывает ту же практику без дополнительной синхронизации. Пометка «Применится при следующем запуске» остаётся верной.

### 4. Тесты и документация

Unit-тест `tests/preferences.test.ts` проверяет запись и чтение значения, а также отсутствие исключения при заблокированном хранилище. E2E-сценарий выбирает «Мягкий белый шум» в меню, перезагружает страницу и проверяет выбранную практику, `src` единственного `<audio>`, скрытую группу длительности, отсутствие автозапуска и совпадение со страницей настроек. Обновляются README, PRODUCT, AGENTS и `docs/specs/audio-tracks.md`.

## Критерии приёмки (checklist)

- [x] Выбор практики в меню «Звук» записывается в `medi:default-practice` и переживает закрытие приложения.
- [x] После перезапуска выбрана именно последняя практика; звук не запускается автоматически, позиция и таймер сброшены.
- [x] Страница настроек показывает эту же практику отмеченной и по-прежнему может задать стартовую практику явно.
- [x] Длительность дыхания остаётся несохраняемой: после перезапуска снова 3 минуты.
- [x] При недоступном `localStorage` приложение работает как раньше, без сообщений об ошибке.
- [x] `npm run check`, `npm test` и `npm run test:e2e` проходят.

## Итого и рекомендация

Выбор практики и явная настройка «Аудио по умолчанию» сливаются в одно значение — это минимальное изменение, которое убирает расхождение между ожиданием пользователя и поведением приложения и не добавляет новых сущностей в интерфейс.

## Открытые вопросы

- Нужно ли так же сохранять длительность дыхания (3/5/10 минут) между запусками? Сейчас она сбрасывается на 3 минуты, потому что запрос касался только трека.
- Не стоит ли переименовать «Аудио по умолчанию» в «Стартовая практика», чтобы связь с выбором в меню «Звук» была очевиднее? Текущий текст сохранён, чтобы не менять продуктовые формулировки без отдельного решения.
